## 2. 验收标准

> 每条标准必须是可测试、可验证的，禁止模糊描述。

### 2.1 功能验收

- [ ] API 接口返回正确的状态码和数据格式
- [ ] 前端正确渲染数据，无空白或错误状态
- [ ] 用户操作产生预期结果（如点击后状态变化）
- [ ] 边界情况处理正确（如空数据、错误输入）

### 2.2 质量验收

- [ ] TypeScript 编译无错误 (`npm run type-check`)
- [ ] ESLint 无错误 (`npm run lint`)
- [ ] 单元测试全部通过 (`npm run test`)
- [ ] 端到端测试全部通过 (`npm run test:e2e`)
- [ ] 无 console.error 或未捕获异常

### 2.3 设计验收

- [ ] 视觉风格与设计系统一致
- [ ] 响应式布局在移动端正常显示
- [ ] 交互反馈清晰（loading、error、success 状态）
- [ ] 无 AI 模板化痕迹（如紫色渐变卡片）

### 2.4 性能验收

- [ ] 页面首次加载时间 < 3s
- [ ] 交互响应时间 < 100ms
- [ ] 无明显内存泄漏

## 3. 端到端测试定义

> 这是 Evaluator 验收的核心依据，必须详细到每个操作步骤。

### 测试场景 1: 正常流程

```
前置条件: 用户已登录，页面正常加载

步骤 1: 用户访问 /todos 页面
预期: 页面显示待办清单列表

步骤 2: 用户点击 "新增" 按钮
预期: 弹出新增表单对话框

步骤 3: 用户输入 "买菜" 并点击保存
预期: 列表新增 "买菜" 条目，对话框关闭

步骤 4: 用户点击条目的复选框
预期: 条目标记为已完成，样式变化

步骤 5: 用户点击删除按钮
预期: 条目从列表中移除
```

### 测试场景 2: 异常流程

```
前置条件: 用户已登录

步骤 1: 用户输入空内容并点击保存
预期: 显示验证错误 "内容不能为空"

步骤 2: 用户输入超长内容（300字）
预期: 显示验证错误 "内容不能超过255字"

步骤 3: 网络断开时点击保存
预期: 显示错误提示 "保存失败，请重试"
```

### 测试场景 3: 边界情况

```
步骤 1: 列表为空时显示空状态
预期: 显示 "暂无待办事项" 提示

步骤 2: 列表有 100 条数据时
预期: 分页显示或虚拟滚动，无卡顿
```

## 4. 完成定义 (Definition of Done)

> 以下所有条件必须 100% 满足，才能标记 feature 为 `passes: true`。

### 4.1 代码完成

- [ ] 所有代码已提交到 feature 分支
- [ ] 代码符合 ARCHITECTURE.md 规范
- [ ] 无 TODO 或 FIXME 注释遗留
- [ ] 关键逻辑有注释说明

### 4.2 测试完成

- [ ] 所有单元测试通过
- [ ] 所有端到端测试通过
- [ ] 测试覆盖率达到要求（Service > 80%，UI > 60%）

### 4.3 文档完成

- [ ] API 有 JSDoc 或 OpenAPI 注释
- [ ] 复杂逻辑有 README 或设计文档
- [ ] `progress.md` 已更新

### 4.4 验收完成

- [ ] Evaluator 评分通过（各维度 >= 6/10）
- [ ] Evaluator 无阻塞问题反馈
- [ ] Playwright 截图验证通过
